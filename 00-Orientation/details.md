## Prerequisites and quick diagnostic

- **Backend transfer:** Explain validation, auth, persistence and one integration test from CRM.
- **Python/SQL baseline:** Write a JSON transformation and a small join without generated code.
- **Product reasoning:** Name a user, their question, a failure and observable success.

Use existing CRM evidence where applicable. A gap triggers targeted review, not a beginner-course restart.

## Complete technical scope

- **Transfer backend skills:** Express handlers → FastAPI routes; Zod → Pydantic; Jest → pytest; Mongoose → ORM boundaries.
- **Choose the user problem:** Book questions; journal connections; non-goals; permitted document corpus.
- **Define answer contracts:** Evidence versus suggestion; no-evidence behavior; ownership.
- **Plan evaluation evidence:** Answerable/unanswerable questions; expected source; fixed synthetic cases.
- **Learn independently:** Read → recall → implement → test → explain; AI assistance boundaries.

## Common mistakes and debugging

### Planning everything

Freeze three non-goals and build the first endpoint next.

### Vague AI success

Turn “helpful answer” into groundedness, citation and abstention criteria.

### Copying a tutorial product

Use your own reflection/journal user stories and corpus.

## Self-check

These are original reasoning prompts, not confirmed ITI questions.

1. What makes the first release small?
2. What counts as prior skill evidence?
3. Why draft evaluation questions now?

<details>
<summary>Answer guide</summary>

**What makes the first release small?**

One user flow, a small corpus, explicit non-goals and observable acceptance criteria.

**What counts as prior skill evidence?**

A specific route, test, schema or commit you can explain and modify.

**Why draft evaluation questions now?**

They expose ambiguous scope and establish a baseline before optimization.

</details>
