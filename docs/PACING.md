# Effort and Pacing

[Home](../README.md) · [Progress](../progress/README.md)

The comprehensive Core is approximately 233–355 focused hours before diagnostic waivers. These are personal learning estimates, not ITI hours or an obligation to finish everything within twelve weeks.

| Availability | Adaptation |
|---|---|
| 15–20 hours/week | Approximately12–24 weeks for Core; S3 produces a demonstrable RAG application earlier |
| 8–10 hours/week | Extend the calendar while retaining prerequisites and security/evaluation gates |
| 25+ hours/week | Spend extra time on failure analysis and review rather than adding frameworks |
| Example18-hour allocation | 4 reading,9 building,3 tests/evaluation/docs,2 foundations or review; adjust as needed |

| Situation | Action |
|---|---|
| Familiar backend topic | Pass a diagnostic and a small Python transfer exercise; skim repeated theory |
| Whole-module waiver | Demonstrate every gate, record evidence and reason, and keep it visible as waived |
| Stuck implementation | Record a blocker, reduce to one behavior, and read to answer a specific question |
| Independent foundations | Progress M02 alongside implementation; do not silently remove it from Core |
| Early job application | Use actual milestones and existing CRM evidence; do not wait for every optional topic |

Completing one familiar subtopic does not waive an entire module. ORM lifecycle, model evaluation, and LLM security may remain new even with substantial backend experience.
