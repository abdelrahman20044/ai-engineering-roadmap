## Prerequisites and quick diagnostic

- **Core project readiness:** Upload, ask, cite, journal connection, history and deletion work end-to-end.
- **Evidence readiness:** CI, holdout, security matrix and traces have reproducible artifacts.
- **Independence:** Modify and test a small feature without generated code.

Use existing CRM evidence where applicable. A gap triggers targeted review, not a beginner-course restart.

## Complete technical scope

- **Reproducible capstone release:** Setup; seed corpus; secrets template; migrations; version manifest.
- **Final evaluation and limitations:** Untouched holdout; raw counts; source/citation results; failure taxonomy.
- **Architecture and technical defense:** ERD; request trace; ADR; provider boundary; agent/no-agent rationale.
- **AI fundamentals interview bridge:** ML leakage; gradients; tokens; embeddings; retrieval; sampling.
- **Backend and operations defense:** Auth; SQL; transaction; async; worker; deployment; trace diagnosis.
- **Career evidence and communication:** Role-specific CV; scoped proposal; ethical claims; status reporting.

## Common mistakes and debugging

### Another demo without evidence

Link reproducible tests, datasets, configs and failure analysis.

### Production claim exceeds deployment

Describe what was exercised and remaining limits precisely.

### Study every optional resource before applying

Use the role checklist and apply after demonstrable core competence.

## Self-check

These are original reasoning prompts, not confirmed ITI questions.

1. How defend a rejected technology?
2. What makes a CV metric credible?
3. How present failure?

<details>
<summary>Answer guide</summary>

**How defend a rejected technology?**

State the requirement, options, evidence, tradeoff and trigger for reconsidering the decision.

**What makes a CV metric credible?**

A reproducible measurement with workload, sample size, environment and configuration.

**How present failure?**

Show the case, root cause, mitigation, verification and remaining limitation.

</details>

## Learning objectives and evidence

- [ ] A reviewer runs the release on synthetic data from a clean checkout.
- [ ] Freeze the config, run holdout once for release assessment and analyze three failures.
- [ ] Present a 5-minute demo and a deeper 20-minute walkthrough with one rejected option.
- [ ] Answer conceptual questions using your own experiment or failure example.
- [ ] Write an endpoint, query and test independently; diagnose a supplied failing trace.
- [ ] Write three evidence-backed CV bullets and a scoped delivery proposal with assumptions and acceptance criteria.
